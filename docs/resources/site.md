# spinupwp_site (Resource)

A SpinupWP site, with its basic auth and backups. Creating a site waits until SpinupWP has finished deploying it. HTTPS is managed with `spinupwp_site_https`.

## Example Usage

```terraform
data "spinupwp_server" "web" {
  name = "my-server"
}

variable "wp_admin_password" {
  type      = string
  sensitive = true
}

variable "preview_password" {
  type      = string
  sensitive = true
}

resource "spinupwp_site" "blog" {
  server_id           = data.spinupwp_server.web.id
  domain              = "blog.example.com"
  site_user           = "blog"
  installation_method = "wp"
  php_version         = "8.3"
  page_cache_enabled  = true
  cron_interval       = 1

  database = {
    name     = "blog"
    username = "blog"
    # password_wo is optional: SpinupWP generates one if it is unset.
  }

  wordpress = {
    title             = "Example Blog"
    admin_user        = "admin"
    admin_email       = "admin@example.com"
    admin_password_wo = var.wp_admin_password
  }

  # Optional: keep the site private. Bump password_wo_version to send a new password.
  basic_auth = {
    username            = "preview"
    password_wo         = var.preview_password
    password_wo_version = 1
  }

  # Optional: at least one schedule. Removing the block turns backups off.
  backups = {
    storage_provider_id = 34 # Account Settings → Storage Providers
    bucket              = "my-site-backups"
    region              = "nyc3"
    include_database    = true

    daily = {
      hours          = [3]
      retention_days = 14
    }

    weekly = {
      days           = [0] # Sunday
      hour           = 4
      retention_days = 60
    }

    monthly = {
      days           = [{ week = "first", day = 1 }] # first Monday
      hour           = 5
      retention_days = 365
    }
  }

  # A typo in domain or site_user would replace (delete) the site.
  lifecycle {
    prevent_destroy = true
  }
}
```

## What can change in place

- `php_version`, `page_cache_enabled`, `cron_interval`, `basic_auth` and `backups` are updated in place.
- `server_id`, `domain` and `site_user` can't change in SpinupWP: changing them **replaces** the site.
- `installation_method`, `dns_provider_id`, `database` and `wordpress` are only used to create the site. Changing them later also replaces it.

Replacing a site deletes it and creates an empty one. Use `lifecycle { prevent_destroy = true }` on sites you care about, and read plans carefully.

When a site is destroyed, its database and backups are kept unless `delete_database` or `delete_backups` is `true`.

HTTPS has its own resource, `spinupwp_site_https`: enabling it often fails until DNS points at the server, and a failure there never affects the site. `basic_auth` and `backups` are applied right after the site is created, so if they fail then, Terraform marks the new site as tainted and recreates it on the next apply.

## Schema

### Required

- `domain` (String) Primary domain. Changing it replaces the site.
- `installation_method` (String) One of `blank`, `wp`, `wp_subdirectory` or `wp_subdomain`. Only used when the site is created; changing it replaces the site.
- `server_id` (Number) ID of the SpinupWP server to create the site on. Changing it replaces the site.
- `site_user` (String) Linux user that owns the site's files and runs its PHP. Changing it replaces the site.

### Optional

- `backups` (Attributes) Scheduled backups. Needs at least one of `daily`, `weekly` or `monthly`. Removing the block turns every schedule off; SpinupWP keeps the storage settings and existing backups. (see [below for nested schema](#nestedatt--backups))
- `basic_auth` (Attributes) HTTP basic authentication, e.g. to keep a staging site private. Removing the block turns it off. (see [below for nested schema](#nestedatt--basic_auth))
- `cron_interval` (Number) Minutes between runs of the server-level WordPress cron: `1`, `2`, `5`, `10`, `15`, `30` or `60`, or `0` to turn it off. Unset keeps SpinupWP's default. Can be changed in place.
- `database` (Attributes) Database to create with the site, on the server's database host. Only used when the site is created; changing it replaces the site. (see [below for nested schema](#nestedatt--database))
- `delete_backups` (Boolean) Delete the site's backups when the site is destroyed. Defaults to `false`.
- `delete_database` (Boolean) Delete the site's database when the site is destroyed. Defaults to `false`.
- `dns_provider_id` (Number) ID of a team DNS provider. When set, SpinupWP points the domain's A record at the server and enables HTTPS with a DNS-validated Let's Encrypt certificate. Only used when the site is created; changing it replaces the site.
- `page_cache_enabled` (Boolean) Whether the Nginx page cache is enabled. Can be changed in place.
- `php_version` (String) PHP version, e.g. `8.3`. Defaults to SpinupWP's default. Can be changed in place.
- `public_folder` (String) Folder Nginx serves, relative to the site's files directory, e.g. `/public` for Laravel. Unset keeps SpinupWP's default (`/`). Changing it replaces the site.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `wordpress` (Attributes) WordPress install settings. Required when `installation_method` is a WordPress method. Only used when the site is created; changing it replaces the site. (see [below for nested schema](#nestedatt--wordpress))

### Read-Only

- `https_enabled` (Boolean) Whether HTTPS is enabled, as of the last refresh. Manage HTTPS with `spinupwp_site_https`.
- `id` (String) Site ID.
- `is_wordpress` (Boolean) Whether SpinupWP detects WordPress on the site.
- `status` (String) Site status reported by SpinupWP, e.g. `deployed`.

## Import

Import a site by its SpinupWP ID (shown in the site's URL in the dashboard).

```terraform
import {
  to = spinupwp_site.blog
  id = "12345"
}
```

```shell
# Import a site by its SpinupWP site ID.
terraform import spinupwp_site.blog 12345
```

SpinupWP doesn't return the create-only arguments, so after import they are recorded from your configuration on the next apply. That apply is an in-place update and never replaces the site. Basic auth and backups are read from SpinupWP; `password_wo` is only sent again when `password_wo_version` changes.
